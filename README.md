# Single-GPU LoRA Rank Ablation for Short-Horizon Demand Forecasting

**Brent Oatis | Applied ML engineering portfolio | October 2026**

This package asks one controlled question: under a fixed one-GPU training budget, does LoRA rank 4, 8, or 16 materially change six-hour electricity-demand forecasting error? Five seeds per rank were run on one NVIDIA Tesla T4. The seed-level error ranges overlap, so this study supports an efficiency choice - rank 4 - but does not establish that any tested rank is more accurate.

## At a glance

| Item | Evidence |
|---|---|
| Controlled factor | LoRA rank: 4, 8, 16; alpha equals rank |
| Fixed factors | Data, chronological split, pretrained backbone, optimizer, epochs, batch size, precision, and evaluation |
| Repeats | 5 seeds per rank; 15 confirmatory runs |
| Primary metric | Test MAPE, reported as mean, sample standard deviation, and min-max |
| Hardware | NVIDIA Tesla T4, 15,360 MiB VRAM; driver 580.82.07; host CUDA 13.0; PyTorch CUDA runtime 12.8 |
| Recommendation | Use rank 4 for this configuration: one-quarter of rank 16's trainable adapter parameters, with no demonstrated accuracy penalty |

## Reproduce the evidence

The notebook is a launcher; the scripts and YAML configuration are the source of truth. A clean Colab reproduction requires a T4-class GPU and enough session time for the matrix.

```bash
git clone <VERIFIED_REPOSITORY_URL>
cd <REPOSITORY_DIRECTORY>
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run_ablation.py --config configs/ablation.yaml --mode all
```

To regenerate summaries and the plot from committed per-run JSON files without retraining:

```bash
python run_ablation.py --config configs/ablation.yaml --mode aggregate
```

The executed environment used Python 3.13.15, PyTorch 2.9.1+cu128, and the exact direct dependencies in `requirements.txt`. `artifacts/environment/environment.json` preserves the full package freeze captured on the run host. Deterministic PyTorch algorithms are requested, cuDNN benchmarking is disabled, data-loader workers are zero, and Python/NumPy/PyTorch seeds are set. Exact bitwise identity across GPU, driver, CUDA, or PyTorch versions is not promised; the target is procedural and statistical reproduction.

## Measured result

| Rank | Seeds | Test MAPE, mean +/- SD | Seed range | Trainable params | Peak GPU memory | Adapt + eval, mean +/- SD |
|---:|---:|---:|---:|---:|---:|---:|
| 4 | 5 | 3.2396% +/- 0.0381 | 3.1860-3.2931% | 2,048 | 123.02 MB | 14.19 +/- 0.14 s |
| 8 | 5 | 3.2487% +/- 0.0466 | 3.1854-3.3143% | 4,096 | 123.42 MB | 13.94 +/- 0.23 s |
| 16 | 5 | 3.2669% +/- 0.0578 | 3.1825-3.3333% | 8,192 | 124.21 MB | 13.94 +/- 0.13 s |

All 15 values are in `artifacts/results/seed_level_results.csv`; rank summaries are in `artifacts/results/summary_by_rank.csv`. The shared backbone took 53.82 seconds to pretrain. Mixed precision was disabled, adaptation batch size was 128, the input sequence was 48 hourly steps, and the forecast horizon was six hours.

### Bounded claim

Under this synthetic dataset, small-transformer architecture, fixed optimizer and epoch budget, single shared backbone, five adaptation seeds, and Tesla T4 software stack, increasing LoRA rank from 4 to 8 or 16 did not produce a separation larger than observed run-to-run variation. Rank 4 is therefore the lowest-cost tested choice. A larger budget could change the conclusion by enabling multiple pretraining seeds, hyperparameter tuning by rank, repeated datasets, real cooperative data, stronger baselines, and out-of-distribution evaluation.

## Intended use and out-of-scope use

**Intended use:** demonstrate controlled ablation design, single-GPU measurement, reproducible reporting, and decision-making under uncertainty. The package can also serve as a template for a real-data pilot after data rights and evaluation criteria are established.

**Out of scope:** production load forecasting, dispatch, capacity planning, billing, safety-critical operations, claims about real customers, or claims that rank 4 is universally optimal. This artifact is not a deployed model and should not drive operational decisions.

## Data and model provenance

- Data are fully synthetic and generated by `src/data.py` with seed 62707; no customer, meter, personal, or proprietary data are used.
- The dataset contains 17,520 hourly steps per cooperative for three source cooperatives and one shifted target cooperative, with demand, temperature, hour-sine, and hour-cosine features.
- Target windows use a chronological 70/15/15 split. The committed file hash is recorded in `artifacts/data/synthetic_demand_metadata.json`.
- The model is authored in this repository: a two-layer, four-head, d_model=64 transformer. It is pretrained once on source traces; only LoRA adapters on query and value projections are trained in the ablation.
- Code and generated artifacts are released under the MIT License. Synthetic traces encode the generator's assumptions and are not representative customer records.

## Limitations

1. **Synthetic-data validity:** programmed seasonality and noise omit real customer behavior, outages, weather extremes, policy changes, and measurement error. Discount all production-performance implications.
2. **Single pretrained backbone:** adaptation seeds vary, but pretraining seed does not. Some apparent rank effects could depend on the shared representation.
3. **No rank-specific tuning:** one optimizer and epoch budget were held fixed for fairness. Higher ranks may need different regularization or learning rates.
4. **Small scale and one GPU class:** the model, horizon, and T4 kernels do not establish scaling behavior for larger models, longer contexts, or other accelerators.
5. **One generated dataset and split:** there is no repeated data-generation seed, cross-cooperative real-data validation, or stress test for distribution shift.
6. **Descriptive uncertainty:** five seeds and min-max overlap support a cautious decision, not a formal equivalence or non-inferiority claim.
